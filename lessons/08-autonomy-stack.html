讲解

第 1 步：三种组织方式

白话类比：做菜。 - 流水线：洗菜工 → 切菜工 → 厨师 → 摆盘，每人只会一件事，交接要有标准格式（中间表示）。 - 端到端：一个全能厨师从头做到尾，看一眼食材直接出菜。 - 双系统：主厨想菜单、下指令（慢），帮厨手上快速执行，看到锅要溢出马上关火，不用问主厨。

经典模块化 端到端 VLA 双系统（System 2 + System 1）
结构 感知 → 状态估计 → 规划 → 控制，各模块独立 图像 + 指令 → 网络 → 动作 慢 VLM（推理、规划）+ 快策略（视觉运动控制）
中间表示 人定义：物体位姿、地图、轨迹 无（网络内部隐变量） 隐向量 / 语言子任务 / 子目标
优点 可解释、可单独测试、可验证 不用手工设计表示，能学到难描述的技能（叠衣服） 兼顾泛化（大模型）和反应速度（小模型）
缺点 接口外的情况处理不了（透明物体、可变形物体） 要大量数据、难调试、推理慢 两层如何对齐、如何联合训练
代表 MoveIt + 位姿估计 + 抓取规划；Nav2 RT-2、OpenVLA、π0 / π0.5 Figure Helix、NVIDIA GR00T N1、Hi Robot、Gemini Robotics

第 2 步：经典流水线的模块

 相机 / LiDAR / IMU
    → 感知：检测、分割、6D 位姿（Grounding DINO + SAM 2、FoundationPose）
    → 状态估计 / SLAM：机器人在哪、地图长什么样（ORB-SLAM3、FAST-LIO、slam_toolbox）
    → 世界模型（这里指"场景表示"）：物体列表、占据地图、3D 场景图
    → 任务规划：行为树 / 状态机 / PDDL / LLM
    → 运动规划：抓取位姿选择 → 无碰撞路径（OMPL / CuRobo）→ 轨迹时间参数化
    → 控制（第 6 章）

优势是每一步都能单独看对不对。弱点是累积延迟（一个个串行跑）和接口脆弱（位姿估计一错，后面全错，且下游无法补救）。

第 3 步：端到端 VLA

VLA 把"感知 → 规划 → 运动生成"合成一个网络：VLM 骨干（看图 + 读指令）+ 动作头（输出一段 action chunk）。细节见 VLA 讲义。

在系统里的位置：

  • 输入：多路相机图像 + 指令 + 机器人本体状态（关节角）；
  • 输出：未来 H 步的关节角 / 末端位姿（例如 π0 是 50 步）；
  • 频率：推理 5–15 Hz，动作执行 50 Hz 左右，靠 action chunk + 插补补上（第 1 章）；
  • 下面仍然是阻抗 / PD 控制（第 6 章）和安全层（第 10 章）。

第 4 步：双系统

System 2（慢） System 1（快）
模型 大 VLM（数十亿参数） 小策略网络（几千万到几亿）
频率 约 1–10 Hz 约 50–200 Hz
做什么 理解场景和指令、拆子任务、给出隐向量 / 子目标 根据最新图像 + 本体状态 + System 2 的指令，输出动作
例子 Figure Helix 公开介绍为 S2 约 7–9 Hz、S1 约 200 Hz；GR00T N1 也分 System 2 / System 1

关键：System 1 不用等 System 2。System 2 异步更新"意图"，System 1 用最新的意图和最新的画面持续出动作，所以遇到突发变化，反应时间由 System 1 决定。更多架构模板见 VLA 面试资料 06。

第 5 步：延迟预算：从"发生"到"反应"要多久

反应时间 = 等下一次采样 + 感知 + 推理 + 传输 + 开始执行。串行流水线里各段相加；并行 / 异步架构里，只看"最快那条闭环"。

一个示意（数字是量级，不是某个产品的实测）：

架构 闭环里有什么 一圈时间 物体被碰走后多久开始转向
模块化串行 相机 33 + 检测 30 + 位姿 40 + 规划 200 + 下发 5 ms ~300 ms 0.3–0.6 s
端到端 VLA（chunk，Tₐ = 0.2 s） 编码 + VLM + 动作头 ~120 ms，每 0.2 s 重想一次 200 ms 0.2–0.4 s
双系统 S1：编码 + 小网络 ~10 ms，100 Hz 10 ms ~0.01–0.05 s（S2 晚些更新意图）

降低延迟的手段：异步推理（执行旧 chunk 的同时算新 chunk）、实时分块（RTC）、模型量化 / TensorRT、把相机和推理放同一块板子避免拷贝、降低图像分辨率。

第 6 步：怎么选

  • 任务结构清楚、对象固定、需要可验证（工厂、仓储）→ 模块化为主，局部用学习（抓取检测、位姿估计）。
  • 任务难以描述、接触丰富、对象多变（家务、叠衣服）→ 端到端 VLA 或双系统。
  • 移动操作 / 长任务 → 上层 LLM/VLM 规划 + 导航栈（Nav2 或导航基础模型）+ 操作 VLA，底层统一的全身控制。
  • 无论哪种：安全层、底层控制、状态估计都保留经典做法。

公式

名称 式子
串行一圈 \(T_{cycle} = \sum_i t_i\)
最坏反应时间（串行） \(t_{react} \lesssim 2\,T_{cycle}\)（刚错过本圈采样）
异步双系统 \(t_{react} \approx T_{S1} + t_{S1}\)，与 \(T_{S2}\) 基本无关

数学原理

  • 延迟求和、采样等待的期望（均匀分布期望 \(T/2\)）。
  • 流水线吞吐 vs 延迟：并行化提高吞吐，不一定降低单次延迟。

关键几行：

c = int(np.ceil(event_s / period_s - 1e-9))      # 事件之后开始的第一圈是第 c 圈
return c * period_s + sum(segments_s) - event_s   # 那一圈结束（开始执行新动作）减去事件时刻

代码里才看得到的 2 件事：

  • - 1e-9 是为了防浮点误差：0.30 / 0.01 在电脑里算出来是 30.000000000000004，不减一点 ceil 会多算一圈。
  • 动画里 S1 的 8 ms 是"刚好在事件那一刻开始一圈"的最好情况；公式表的 18 ms 是"刚错过"的最坏情况。两个数都对，问的不是同一件事。
